第1章　操作系统概述

这一章回答三个问题：操作系统是什么、它替应用程序做了哪些事、这些能力是怎样一步步演化并组织成系统的。读完后你应能画出「硬件—OS—应用」三层结构，说清四大功能，并解释多道批处理与分时系统的切换差别。

1.1　从功能清单到操作系统定义

素材位置：第01章 操作系统概述（2学时）.pdf，pp.21、21–22、32–36

关键概念：操作系统（Operating System）

一句话定义：一个大型的程序系统，负责计算机系统软硬件资源的分配，控制和协调并发活动，并提供用户接口（p.35）。

边界与适用条件

  • 定义含三件事：资源分配、控制和协调并发活动、提供用户接口；素材把后两点浓缩为「两个关键：管理并调度资源、为用户提供接口」（p.35）。
  • 地位是「中间层」：下接裸机与机器语言，上接系统程序与应用程序（p.37 的层次图）。
  • p.21 用三类价值描述它：交互/接口、资源管理、资源共享。

不是什么：不是应用软件，区别也不在大小、规模或复杂程度（p.39 判断题 4 正是要排除这一误解）；不是硬件本身，而是建立在硬件之上的系统程序。是否承担资源管理与硬件抽象、以及运行在什么 CPU 态，才是分界（见 §2.2）。

两种表征

  • 表征一：三层次结构：图 1-1：应用程序 → 操作系统 → 硬件/资源，操作系统居中提供接口与资源管理（p.21）。
  • 表征二：一次调用链：图 1-2：fprintf → write → load/seek/out → 硬件，逐层屏蔽细节（p.36）。

可检验动作：拿 p.34 的七个追问逐条说出由哪项 OS 功能承接；再判断「一个只提供窗口界面、不管理内存与 CPU 的软件」是否仍符合 p.35 的定义。

复现：§1.2 用并发性解释为什么要「控制和协调并发活动」；§1.3 把资源分配拆成四大功能；§2.2 用 CPU 的态解释这种分层在硬件上如何被保护。

素材先给出一层直观认识：操作系统位于应用程序与计算机硬件之间，同时承担交互/接口、资源管理、资源共享三类价值（p.21 的结构图）。图上，显示器、键鼠、打印机、CPU、内存是「硬件/资源」，应用程序在另一侧，操作系统居中。

图 1-1　三层次：硬件资源 → 操作系统 → 应用程序（p.21 结构图）
应用程序（用户直接使用的软件） → 操作系统（交互/接口 · 资源管理 · 资源共享） → 硬件/资源（CPU、内存、显示器、键鼠、打印机）

p.32 把「初步认识」整理成六项基本功能：提供操作界面、控制程序运行、管理系统资源、配置系统参数、监控系统状态、工具软件集合。p.34 进一步用一个具体问题把它们串起来：应用程序运行需要操作系统提供哪些支持？——从查找并读取 exe、启动程序、分配内存，到 printf 如何输出字符、程序独占 CPU 怎么办、程序结束如何退出、如何编译/链接。

1.2　地位、三个特性与「并发」带来的问题

素材位置：第01章 操作系统概述（2学时）.pdf，pp.37–41

关键概念：并发性（concurrency）

一句话定义：操作系统同时处理多个任务的能力（p.38）。

边界与适用条件

  • p.41 的例子表明 OS 可在任意时刻暂停/继续任何程序，因此同一段程序在并发环境下可能有不同输出结果。
  • p.69 用「并行（宏观上）／串行（微观上）」描述多道批处理：宏观上多道程序都在推进，微观上 CPU 仍逐道执行。
  • 与共享性、不确定性并列为 p.38 的三个特性；不确定性由中断机制支撑，见 §2.4。

不是什么：并发不等于「同一时刻一定有多个 CPU 在跑」；也不等于结果随机就可以不做控制——p.41 恰恰用结果不唯一来说明需要引入进程与同步机制。

两种表征

  • 表征一：手算例子：表 1-3 用全局变量 i 的四种输出，展示暂停点不同导致结果不同（p.41）。
  • 表征二：宏观/微观对照：p.69「多道、并行（宏观上）、串行（微观上）」，配合 p.68 的时分/空分复用图。

可检验动作：对表 1-3 的每一行，写出一种能产生该输出的 A/B 指令交错次序；再回答：若给 i 加互斥保护，哪些输出会消失？

复现：§1.3 引入进程管理；§1.5 的多道程序设计与分时技术都以并发为前提；§2.4 的中断是 OS 能「在任何时刻暂停程序」的硬件基础。

p.37 的层次图给出 OS 的地位：从下往上是裸机（硬件部分）→ 微程序 → 机器语言 → 系统程序（编译程序、汇编程序、装入程序、编辑程序、调试程序等）→ 各种各样的应用程序。操作系统属于系统程序这一层，向下贴近机器语言与硬件，向上支撑应用。

图 1-3　p.37 的系统层次（由下往上）
裸机 / 硬件（最底层） → 微程序 → 机器语言（硬件之上的指令形态） → 系统程序 / OS（编译、汇编、装入、编辑、调试等） → 应用程序（用户直接使用的软件）

p.38 列出操作系统的三个特性：并发性（同时处理多个任务的能力）、共享性（为多个并发任务提供资源共享）、不确定性（具有处理随机事件/中断的能力，素材同时点了中断处理能力与自动化能力）。

1.3　四大功能：进程 / 存储 / 设备 / 文件管理

素材位置：第01章 操作系统概述（2学时）.pdf，pp.41–52

关键概念：进程（process）的引入

一句话定义：在并发环境下，「程序」不足以描述程序的运行过程并确保运行结果的正确，因此引入「进程」来描述一次运行中的程序（p.41）。

1.5　发展与演变：四个典型阶段

素材位置：第01章 操作系统概述（2学时）.pdf，pp.56–77

关键概念：多道程序设计技术（multiprogramming）

一句话定义：内存中同时存放多道程序，当某道程序因请求 I/O 等原因不能继续运行时，监控程序/OS 调度另一道程序投入运行，使 CPU 尽量保持忙碌、提高系统效率（p.66）。

边界与适用条件

  • 触发条件是「当前程序不能继续」而非「时间片到」，这是与分时技术的分界（p.66 对 p.73，详见本节推断说明）。
  • p.68 把资源共享实现分成时分复用与空分复用；p.69 概括特点为多道、宏观并行、微观串行，并称其为现代 OS 的雏形。
  • 代价见 p.70：作业处理时间长、运行过程不确定、交互能力差。

不是什么：不是「多个 CPU 同时执行多道程序」；也不是分时系统的时间片轮转。它解决的是 CPU 在 I/O 等待期间空转的问题。

两种表征

  • 表征一：作业切换流程：表 1-7：装入 → 运行 →（I/O 时 CPU 空闲）→ 撤出 → 下一作业（p.61–62）；可逐步演示。
  • 表征二：时分 / 空分：p.68：多个程序「同时」在计算机上运行，CPU 按时段复用、内存按单元复用。

可检验动作：用 p.58 的 100min = 50 + 10 + 40 估算手工操作阶段的 CPU 利用率；再说清：若把 10min 的运行改成「I/O 时切到另一道程序」，CPU 空闲会如何变化。

复现：§1.6 的实时系统延续「时限」这一维度；§2.4 的中断与 §2.5 的中断响应是「程序被暂停、随后恢复」的硬件实现；本课程第 4–6 章（素材未提供）才展开调度算法。

p.56 把操作系统发展划为四个典型阶段：① 手工操作（无操作系统，40 年代–50 年代初）；② 单道批处理系统（50 年代）；③ 多道批处理系统（60 年代初）；④ 分时操作系统（60 年代中–至今）。本节按「为什么出现 → 怎么工作 → 解决了什么 → 留下什么问题」的顺序读。

1.7　操作系统的逻辑结构：整体式 / 层次 / 微内核

素材位置：第01章 操作系统概述（2学时）.pdf，pp.94–107

关键概念：微内核结构（客户/服务器结构）

一句话定义：操作系统 = 微内核 + 核外服务器；微内核只保留最基本的核心功能与服务，核外服务器完成 OS 绝大部分功能（p.103–104）。

边界与适用条件

  • p.104 列出微内核三项职责：与硬件紧密相关的处理；基本 I/O、时钟、中断、进程等基本功能；客户与服务器之间的通信。
  • 核外服务器（进程/线程服务器、虚存服务器、设备管理服务器等）以进程形式运行在用户态，等待客户提出请求。
  • p.106 的代价是进程状态频繁切换、系统效率低；收益是内核精练、便于剪裁移植、稳定性和安全性高。

不是什么：不是「把宏内核简单拆成几个文件」；也不是「所有服务都在内核态」。分界在于地址空间与 CPU 态：宏内核把图形、驱动、文件系统与内核放在同一地址空间，微内核把服务器放到用户态。

两种表征

  • 表征一：结构图：图 1-6 与 p.103 的图：客户（应用）→ 微内核 → 内存/文件/网络/设备服务进程。
  • 表征二：对照表：表 1-12 按特点、优点、缺点、代表四列逐项比较（p.106）。

可检验动作：把「文件系统」「中断处理」「设备驱动」分别放到微内核或核外服务器，并依据 p.104 的三项职责说明理由；再解释为什么这样会带来 p.106 所说的效率损失。

复现：§2.2 解释内核态/用户态的硬件支持；§2.5 的中断响应说明「交换 CPU 的态」这一动作；p.105 列出的 Minix 与 §1.6 的 MINIX 是同一系统。

2.2　CPU 的态、特权指令与态的转换

素材位置：第02章 操作系统的硬件基础（2学时）.pdf，pp.5–14

关键概念：CPU 的态（mode，核态 / 用户态）

一句话定义：态描述指令使用和资源访问的权限（p.6）；核态能访问所有资源、执行所有指令，用户态只能访问部分资源（p.7）。

边界与适用条件

  • 硬件按态区分 CPU 状态，OS 按进程区分 CPU 状态（p.8），两者是不同维度的观察。
  • p.9 由模式位与 CPL/RPL/DPL 特权级比较，在指令执行前做权限判断。
  • p.14 列出用户态→核态的四种情形（请求 OS 服务、内部中断/程序错误、企图执行特权指令、发生中断）与核态→用户态的一般途径（中断返回 IRET）。

不是什么：不是进程状态（就绪/运行/阻塞），也不是「CPU 有几个核心」。态是硬件提供的权限屏障，用来落实 p.6 的软件分级。

两种表征

2.4　中断机制：定义、分类、断点与现场

素材位置：第02章 操作系统的硬件基础（2学时）.pdf，pp.21–23

关键概念：中断（interrupt）

一句话定义：CPU 对突发的外部事件的反应过程或机制：收到中断信号后停止当前工作，转去处理事件，处理完回到断点继续原工作（p.21）。

边界与适用条件

  • p.22 从三个维度分类：强迫/自愿、外中断/内中断（俘获）、可屏蔽/不可屏蔽；其中可屏蔽的划分只针对外中断。
  • p.23 区分断点（下一条指令地址 CS:IP）与现场（相关寄存器集合），二者保护/恢复的责任方不同。
  • p.27 把引入中断的目的列为：实现并发活动、实现实时处理、故障自动处理。

不是什么：不是「程序出错」的同义词：p.22 的自愿中断（INT 21H、访管指令）是程序主动发起的正常服务请求。也不是「进程切换」本身，但它为切换提供硬件入口。

两种表征

  • 表征一：流程图：图 2-4：主程序 → 中断源 → 断点 → 中断服务程序 → 返回（p.21、p.27）。
  • 表征二：分类表：表 2-5 用三组对照判定一条中断同时具有哪些属性（p.22）。

可检验动作：判断 INT 21H 在 p.22 的三组分类中分别属于哪一类；再回答：若把断点误当成现场，会漏掉哪些需要保存的信息？

复现：§2.5 把中断展开为六步响应过程；§2.6 的 BIOS 中断（INT 13H 等）是它的具体应用；§1.2 的「不确定性」依赖中断处理能力。

p.21 给出定义：中断指 CPU 对突发的外部事件的反应过程或机制——CPU 收到外部信号（中断信号）后，停止当前工作，转去处理该外部事件，处理完毕后回到原来工作的中断处（断点）继续原来的工作。

2.7　操作系统启动过程与系统生成（本章重点）

素材位置：第02章 操作系统的硬件基础（2学时）.pdf，pp.45–74

关键概念：初始引导（initial boot）

一句话定义：启动过程的第一阶段，目的是把 OS 内核装入内存并使之开始工作、接管计算机系统（p.48–p.49）。

边界与适用条件

  • p.49 给出引导程序 MBR（Master BOOT Record）及 GRUB、bootmgr / NTLDR / LILO 等实现。
  • p.47 说明启动初期处于实模式（1MB 空间、单任务），之后进入保护模式（4GB、支持多任务）；实模式末尾 256K【C0000–FFFFF】留给 BIOS。
  • p.53 的 Linux 链把初始引导具体化为 POST → 启动程序 → MBR → KERNEL 映像 → 自解压执行 → 内核初始化 → init。

不是什么：不是「系统初始化」（那是 p.52 的第三阶段，为用户准备文件系统、网络、控制台、图形界面），也不是「操作系统生成」（那是从源码编译出新内核，p.61–p.71）。

两种表征

  • 表征一：三阶段表：表 2-12：初始引导 / 核心初始化 / 系统初始化各自的目的与工作（p.48–p.52）。
  • 表征二：Linux 启动链：表 2-13 与图 2-6：从 POST 到 init 再到 shell 的七步，可逐步演示。

可检验动作：用上方演示逐步走完 Linux 启动链，指出「核心初始化」与「系统初始化」分别落在哪一步；再解释为什么 p.47 的实模式 1MB 空间里必须留出末尾 256K 给 BIOS。

复现：§2.6 的 BIOS 自举是本阶段的前置；§2.2 的保护模式与 CPU 的态共同决定内核接管后的权限；§1.7 的内核结构决定「哪些功能在内核初始化时进入内核态」。

易错点：启动 ≠ 生成

「启动过程」是每次开机都发生的运行时流程（加电 → 引导 → 初始化 → 登录）；「操作系统的生成」是一次性的构建流程（获取源码 → 配置 → 编译 → 安装 → 配置启动项）。两者都涉及「让内核可用」，但一个在执行内核，一个在产出内核。

核态 / 用户态（kernel mode / user mode）态描述指令使用和资源访问的权限；核态可执行所有指令。管态介于两者之间；态不等于进程。第2章 p.6–9
特权指令（privileged instruction）只有可信软件/核态可执行的指令。分 I/O、修改特殊寄存器、改变机器状态三类。第2章 p.12
模式位 / 特权级（mode bit / privilege level）CPU 用模式位标明当前态，指令执行前比较 CPL/RPL/DPL。素材以 Intel 的 CS/DS/SS/ES 为例。第2章 p.9
中断（interrupt）CPU 对突发外部事件的反应过程或机制。含强迫/自愿、外/内（俘获）、可屏蔽/不可屏蔽三组分类。第2章 p.21–22
断点（breakpoint (of interrupt)）程序中断的地方，即下一条指令地址 CS:IP。不是现场；现场是相关寄存器集合。第2章 p.23
现场（context / scene）程序正确运行所依赖的信息集合（相关寄存器）。保护/恢复由程序与硬件共同完成，见 PUSH/IRET 序列。第2章 p.23、p.26
中断向量表（interrupt vector table）按中断号 X 存放服务程序入口 Seg:Off，位置为 4*X ~ 4*X+3。入口地址不等于中断号本身。第2章 p.25
中断返回（IRET）恢复断点与现场的硬件指令。也是核态返回用户态的一般途径；不同于普通 RET。第2章 p.14、p.26
基本输入输出系统 / 固件（BIOS / firmware）位于 F0000–FFFFF 的固件，负责 POST、CMOS、基本 I/O、自举。BIOS 中断类型号 10H~1FH，区别于 DOS 的 INT 21H。第2章 p.30、p.36、p.44
加电自检（POST）加电或复位后执行的硬件初始化，出错用喇叭鸣叫提示。JMP 指令在 FFFF0 单元；是启动链的起点。第2章 p.31
柱面-磁头-扇区（CHS）BIOS INT 13H 使用的扇区定位机制。柱面与磁头 0 起、扇区 1 起；单碟双面 2 个磁头。第2章 p.39–40
实模式 / 保护模式（real mode / protected mode）实模式按 8086 方式访问 1MB、单任务；保护模式寻址 4GB、支持多任务。实模式 1MB 中末尾 256K 留给 BIOS。第2章 p.47
主引导记录（MBR）初始引导阶段的引导程序，把 OS 内核装入内存。素材举 GRUB、bootmgr/NTLDR/LILO 等实现。第2章 p.49
init 进程（init）Linux 中系统所有进程的祖先，进程号 = 1。出现在内核启动之后、登录之前。第2章 p.54
操作系统的生成（OS generation）获取源码 → 配置 → 编译 → 安装模块 → 配置启动项，产出新内核。与每次开机的「启动过程」不是同一件事。第2章 p.61–71
