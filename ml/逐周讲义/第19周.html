第19周 / 静态讲义

公平对照：把搜索预算与选择规则写进实验

01公平比较首先回答：你想比较什么

比较“方法在给定搜索预算内能做到什么”和比较“同一学习率下谁更好”是不同问题。两种方法的可训练空间与有效更新尺度不同，共用一个学习率可能恰好适合其中一个。主线采用前者：固定基础检查点、训练数据、最大更新步数和预测token预算，各方法在相同候选数内选择自己的配置。

候选是一次完整的可执行配置。全量微调用6档学习率；LoRA选r=2、8，每档秩各3档学习率，共6个候选。不要把“每种秩各6次”算成LoRA只搜6次；额外改变alpha、插入层或偏置策略也增加配置维度。开发选择前列出全部ID，失败运行也保留，不能只展示成功的那几次。

不适配基线没有训练学习率，所以不需要为了凑数量重复搜索。它仍须在相同A/B开发数据上评价，作为(收益0，遗忘0)的参考。第19周只做小型开发试验：相同基础检查点和配对批次顺序能减少无关差异，但不能消除全部随机性。正式重复留到第22周。

训练token数必须数真正参与损失的token。如果padding没有计分，不能按张量总长度夸大预算；梯度累积时多个微批共同构成一次参数更新，更新步数相同不一定token相同。保持这些预算后仍要测时间与峰值资源，因为冻结参数和额外低秩分支改变了计算。

一起算一个例子

六组预算怎样公平分配

  1. 全量配置F1–F6对应6个学习率。

  2. LoRA配置L1–L3为r=2的3档学习率，L4–L6为r=8的3档。

  3. 12组都训练48000个被计分token。若F2失败，记录失败；不能悄悄给F2额外3次机会。

公平是事先限定同类机会，并报告实际成本；不是所有超参数取相同数值。

02把偏好写成能执行的选择规则

只有B损失最小这一条规则，会允许模型用大量旧域退化换取一点新域进步。这里使用一个明确的教学选择规则：旧域遗忘不超过0.2，再选择B开发损失最小的候选；并列时按候选ID排序。0.2不是普遍合理的阈值，真实项目需在看最终测试前说明为何选择它，也可改成预先固定的其他规则。

若没有候选满足约束，应报告本预算下无可行配置，而不是偷偷把0.2改成0.3。你可以开启有记录的新开发版本扩大预算，但必须在最终测试之前完成，并保留旧结果。主结果比较各方法经同一规则选出的配置，秩2与秩8分项结果另放附表，避免只保留对自己有利的一项。

同时观察所有候选的收益—遗忘散点。有些点被另一个点同时在两个目标上超过，属于可支配候选；未被支配的点形成取舍边界。边界本身不是唯一赢家，因为使用者对遗忘的容忍不同。选择规则把偏好说清，散点图把被选结论以外的信息保留下来。

点击放大

先筛选遗忘约束，再在可行候选中最小化B开发损失。

逐个认识符号

  • F_A：候选旧域遗忘

  • tau：预先固定的容忍阈值，此教学例为0.2

  • c：候选配置，c*：被选择的配置

  • L_B(c)：该候选在B开发集的平均token交叉熵

一起算一个例子

为什么不选B损失最低的F3

  1. 基础A损失0.4、B损失1.6。F3的A/B损失为0.62/0.90，遗忘0.22，超出0.2。

  2. F4为0.59/1.00，遗忘0.19、收益0.60，满足约束。

  3. LoRA的L5为0.50/1.10，遗忘0.10、收益0.50；L6虽B损失0.95，却遗忘0.24。

  4. 按相同规则选择F4和L5。

F4新域收益更大，L5旧域保留更好；当前数据并没有给出无条件的全局赢家。

03把失败变成能定位的问题，而不是抹掉的数据

先对每种方法各跑一个50–200步试验，核对损失有限、参数确实更新、时间与显存可承受，再按冻结的候选清单运行。数值发散用nonfinite标记；超预算用timeout或OOM标记；程序异常保留日志。训练完成但性能差是有效负结果，不应和程序根本未执行混为一类。

如果LoRA全部几乎没学习，先查零初始化路径、优化器集合和学习率范围，不能立即宣布论文错了。若只有高学习率失败，这可能就是敏感性的一部分。修实现错误会改变结果含义，应修复后对受影响的方法按同一协议重跑；不要把错误实现与修复实现混入一张主比较表。

读2024论文时抽取“作者比较什么、哪些条件固定、如何选择超参数、学习与遗忘分别怎么量测”四格，不照搬结论。你的像素模型、颜色置换和小预算与论文领域适配不同，结果方向相同只说明一个相似现象；方向相反也未必反驳原论文。

本周交付表至少包含候选ID、方法、秩、学习率、基础检查点ID、训练token、A/B开发损失、耗时、峰值资源、运行状态和选择理由。程序先用构造表验证筛选逻辑；真实结果填同一结构后再生成报告。

一起算一个例子

一个发散候选怎样进入报告

  1. F6在第37步出现非有限损失，实际消耗17760个token。

  2. 保留F6的候选配置、失败步、耗时和日志，不给它虚构“最终损失”。

  3. 选择器排除无法得到有效开发损失的候选，并报告全量方法6次中1次失败。

失败记录属于预算与稳定性证据，但不能用随便填的巨大数字伪装可比较损失。

Python与C++机制示例

下面的小程序验证关键机制；完整项目须按本周交付要求另行完成。

Python

"""Synthetic development results; exercise a predeclared selection rule."""
# STEP 1
base_a, base_b, forgetting_limit = 0.4, 1.6, 0.2
# id, rank, learning rate, loss_A, loss_B, training tokens
full = [("F1",0,.00001,.44,1.50,48000),("F2",0,.00003,.50,1.30,48000),
        ("F3",0,.0001,.62,.90,48000),("F4",0,.0003,.59,1.00,48000),
        ("F5",0,.001,.80,1.20,48000),("F6",0,.003,1.00,1.40,48000)]
lora = [("L1",2,.0001,.41,1.55,48000),("L2",2,.001,.46,1.40,48000),
        ("L3",2,.01,.54,1.25,48000),("L4",8,.0001,.43,1.45,48000),
        ("L5",8,.001,.50,1.10,48000),("L6",8,.01,.64,.95,48000)]

# STEP 2
assert len(full) == len(lora) == 6
assert len({r[5] for r in full + lora}) == 1
def choose(rows):
    eligible = [r for r in rows if r[3] - base_a <= forgetting_limit + 1e-12]
    assert eligible, "No feasible candidate: report failure, do not change the rule."
    return min(eligible, key=lambda r: (r[4], r[0]))

# STEP 3
best_full, best_lora = choose(full), choose(lora)
assert best_full[0] == "F4" and best_lora[0] == "L5"
assert min(full, key=lambda r:r[4])[0] == "F3"

# STEP 4
print("SYNTHETIC DEV TABLE; not a training result")
print("candidate_counts=6,6 training_tokens_each=48000")
for row in [best_full, best_lora]:
    print(f"selected={row[0]} rank={row[1]} gain={base_b-row[4]:.6f} forgetting={row[3]-base_a:.6f}")
print("unconstrained_F3_rejected=PASS test_used=False")

C++

// Synthetic development results; exercise a predeclared selection rule.
#include <algorithm>
#include <cassert>
#include <iomanip>
#include <iostream>
#include <string>
#include <vector>
// STEP 1
struct Row { std::string id; int rank; double lr, a, b; int tokens; };
int main() {
    const double base_a=.4, base_b=1.6, limit=.2;
    const std::vector<Row> full{{"F1",0,.00001,.44,1.50,48000},{"F2",0,.00003,.50,1.30,48000},
        {"F3",0,.0001,.62,.90,48000},{"F4",0,.0003,.59,1.00,48000},
        {"F5",0,.001,.80,1.20,48000},{"F6",0,.003,1.00,1.40,48000}};
    const std::vector<Row> lora{{"L1",2,.0001,.41,1.55,48000},{"L2",2,.001,.46,1.40,48000},
        {"L3",2,.01,.54,1.25,48000},{"L4",8,.0001,.43,1.45,48000},
        {"L5",8,.001,.50,1.10,48000},{"L6",8,.01,.64,.95,48000}};

    // STEP 2
    assert(full.size()==6 && lora.size()==6);
    for(const auto* rows:{&full,&lora}) for(const auto& row:*rows) assert(row.tokens==48000);
    auto choose=[&](const std::vector<Row>& rows) {
        std::vector<Row> eligible;
        for(const auto& r:rows) if(r.a-base_a<=limit+1e-12) eligible.push_back(r);
        assert(!eligible.empty());
        return *std::min_element(eligible.begin(),eligible.end(),[](const Row& a,const Row& b){
            return a.b<b.b || (a.b==b.b && a.id<b.id);
        });
    };

    // STEP 3
    const Row best_full=choose(full), best_lora=choose(lora);
    assert(best_full.id=="F4" && best_lora.id=="L5");
    assert(std::min_element(full.begin(),full.end(),[](const Row& a,const Row& b){return a.b<b.b;})->id=="F3");

    // STEP 4
    std::cout<<std::fixed<<std::setprecision(6);
    std::cout<<"SYNTHETIC DEV TABLE; not a training result\n";
    std::cout<<"candidate_counts=6,6 training_tokens_each=48000\n";
    for(const auto& r:{best_full,best_lora})
        std::cout<<"selected="<<r.id<<" rank="<<r.rank<<" gain="<<base_b-r.b<<" forgetting="<<r.a-base_a<<'\n';
    std::cout<<"unconstrained_F3_rejected=PASS test_used=False\n";
}

逐步解释

构造候选表

Python元组依次存ID、秩、学习率、A损失、B损失、token数；C++用Row字段使含义显式。输入是教学构造开发表，没有训练。

自查：指出LoRA总候选数为何是6。

筛选再排序

先核对候选数和token预算，然后按遗忘阈值筛选。Python min(key=...)与C++ min_element比较器都按B损失、ID排序，确保并列规则固定。

自查：把阈值改为0.05，预测哪些候选仍可行。

验证有约束与无约束选择不同

断言F4和L5被选，同时无约束B最小值是F3，说明选择规则真正生效。断言是针对该教学夹具的预期，不是现实模型必须选同一ID。

自查：解释F3为什么不是程序漏选。

同时输出两项差值

对两种选择都打印收益和遗忘，不只输出胜负标签。test_used=False描述本程序只用了构造开发表；真实工程须依靠文件用途与记录保证。

自查：依据输出给出带条件的比较句。

练习与参考答案

练习1

基础：LoRA有3档秩、每档4个学习率，而全量只有6个学习率，候选预算一样吗？

提示：

把笛卡尔积展开。

参考：

不一样：LoRA共12组，全量6组。可把LoRA缩至2×3或把全量增至12，但必须提前约定并记录成本；不适配基线无须凑数。

练习2

实践：阈值改为0.05，手算程序选择。

提示：

A基础0.4，因此候选A损失不得超过0.45。

参考：

全量仅F1的0.44满足，B损失1.50；LoRA L1的0.41与L4的0.43满足，L4的B损失1.45更小。结果随使用偏好改变，不代表旧阈值计算错误。

练习3

迁移：全量运行60秒、LoRA90秒，但LoRA可训练参数更少，矛盾吗？

提示：

参数量不是所有计算成本。

参考：

不矛盾。实现、矩阵规模、分支开销、内存访问和硬件利用率都可能影响时间。先确认同步计时、批大小、token数与设备一致，再报告实测；不能用理论参数比覆盖实际记录。

自测

1. 公平调参最接近哪种做法？

  1. 只报告最好一次
  2. 只给LoRA更多机会
  3. 两种方法固定同一学习率
  4. 相同总候选预算，各自选择合适配置

参考：D

2. F3的遗忘0.22，阈值0.2，应？

  1. 约束失败并排除选择
  2. 四舍五入成0.2强行通过

  4. 直接看测试集

3. 候选数相同能保证训练时间相同吗？

  1. 仅秩为2时
  2. 只要基础相同就能
  3. 不能，需实测
  4. 必然

4. 一次种子LoRA更好可以说明？

  1. 所有颜色置换都更好

开放讲解题

为什么需要不适配基线？

它说明不花适配预算时的A/B水平，防止把本来就会的能力归功于微调，也给收益/遗忘差值提供同一参照。

怎样描述F4与L5而不硬选赢家？

在构造开发表和遗忘≤0.2规则下，F4收益0.60、遗忘0.19；L5收益0.50、遗忘0.10。前者学习更多，后者旧域退化更少；实际项目需重复并报告资源。
