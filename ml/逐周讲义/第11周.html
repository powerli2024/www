卷积的局部假设：从四次乘加到CNN对照

011 为什么图片需要保留空间关系

把8×8图像展平为64个数后，MLP仍能学习，但网络结构没有明确告诉它哪些像素彼此相邻。卷积引入一种假设：局部组合有意义，而且同一局部模式可能在不同位置出现。因此一个小窗口在整张图上滑动，反复使用同一组权重。局部连接限制一次看到的范围，参数共享让各个位置使用同一种检测规则。

卷积核并非天生就是边缘检测器。手工给定的核可能计算某种差异；训练得到的核则由损失与数据决定。一个输出通道对应一个核组，它跨越所有输入通道后求和。多个输出通道可以学习不同特征，而不是简单复制同一张结果。

深度学习库中常说的二维卷积通常计算互相关，即不先翻转核。数学教材的离散卷积会翻转核，二者都可以学习权重，但手算与代码必须遵循同一约定。本例明确采用互相关，stride=1、padding=0，不使用偏置，3×3输入配2×2核得到2×2输出。

边界处理影响结果。padding补零让核能覆盖边缘，但补的0不是真实像素；stride控制每次移动距离；dilation在核元素间留间隔。学习时先掌握最简单情况，再按公式核对输出尺寸。不能仅凭程序不报错就认定空间尺寸正确。

022 参数共享如何改变梯度与参数量

同一个核权重参与多个输出，因此损失对它的梯度是各位置贡献之和。对左上核权重k₀₀，每个输出的局部导数是该窗口左上像素。若损失是4个输出到0的一半MSE，上游导数为输出除以4，再分别乘对应输入，最后累加。第9周学的链式法则完全适用，变化的是同一参数出现了多条路径。

参数量不随输出空间位置直接增加：一个标准卷积层有C_out×(C_in×K_h×K_w+1)个参数，最后的1来自每个输出通道的偏置。关掉bias就去掉这一项。局部窗口重复使用同一核，所以一张图变大通常增加计算量，却不增加这一层的参数数。

但整个CNN不一定比MLP参数少。卷积后若把很多特征图全部展平接一个大分类头，参数量会集中在分类头。比较应列出每层及总参数，而非用“CNN”这个名字推断轻量。参数数也不能单独代表训练耗时：同一参数可在许多空间位置重复使用。

033 从机制程序走到项目A中的CNN

程序先计算固定核输出，再手写共享核梯度，最后用中心差分核对k₀₀。两语言使用同一数据与循环顺序。Python列表切片row[:]复制行，否则浅拷贝外层列表后修改核元素会连带修改原核；C++嵌套array按值复制。学习重点是每一个循环索引对应哪个几何位置。

接入PyTorch时，digits批数据应整理成(N,1,8,8)。一个可读的起点是Conv2d(1,8,3,padding=1)→ReLU→Flatten→Linear(512,10)。Conv2d的参数依次表示输入通道、输出通道和核大小，padding=1保持8×8空间大小；Flatten只合并非批维，不能把不同样本混在一起。输出仍是10类logits。

先复制项目A现有训练与评估流程，只替换网络。保持同一开发折、相同候选预算、可比训练token或样本呈现次数，并另外记录实际时间。MLP和CNN都要完成小批次过拟合检查。若使用像素除以16这种预先规定的固定缩放，不从数据估计统计量；若用均值标准差，则只在对应训练折拟合。

比较结果不预设CNN获胜。digits图像小且较居中，数据量有限，卷积假设的优势可能不明显；不同正则、优化预算也会影响结果。若差异小，报告各折分数和错误分布，不把一两张图的改善当作普遍优势。像素平移测试可以观察局部稳定性，但卷积的平移等变不等于最终分类完全平移不变，padding、步幅和展平分类头都会影响它。

Python

"""Cross-correlation, shared-kernel gradient and parameter counting."""
# STEP 1
image = [[1.,2.,0.],[0.,1.,3.],[2.,1.,0.]]
kernel = [[1.,0.],[0.,-1.]]
def conv(x, k):
    return [[sum(x[i+a][j+b]*k[a][b] for a in range(2) for b in range(2))
             for j in range(2)] for i in range(2)]
# STEP 2
out = conv(image,kernel)
loss = sum(v*v for row in out for v in row)/8
grad = [[sum(out[i][j]*image[i+a][j+b] for i in range(2) for j in range(2))/4
         for b in range(2)] for a in range(2)]
# STEP 3
eps = 1e-5
def objective(k):
    return sum(v*v for row in conv(image,k) for v in row)/8
kp, km = [row[:] for row in kernel], [row[:] for row in kernel]
kp[0][0] += eps
km[0][0] -= eps
numeric = (objective(kp)-objective(km))/(2*eps)
assert abs(grad[0][0]-numeric) < 1e-8
# STEP 4
print('output='+' '.join(f'{v:.1f}' for row in out for v in row))
print(f'half_mse={loss:.6f} gradient00={grad[0][0]:.6f}')
print(f'gradient_check={abs(grad[0][0]-numeric)<1e-8}')
conv_params = 8*(1*3*3+1)
cnn_params = conv_params+(8*8*8)*10+10
mlp_params = 64*32+32+32*10+10
print(f'conv_params={conv_params} tiny_cnn_params={cnn_params} mlp_params={mlp_params}')

C++

#include <array>
#include <cmath>
#include <iostream>
#include <iomanip>
#include <cassert>
using Image=std::array<std::array<double,3>,3>;
using Mat=std::array<std::array<double,2>,2>;
// STEP 1
Mat conv(const Image& x, const Mat& k) {
    Mat out{};
    for(int i=0;i<2;++i) for(int j=0;j<2;++j)
        for(int a=0;a<2;++a) for(int b=0;b<2;++b)
            out[i][j]+=x[i+a][j+b]*k[a][b];
    return out;
}
double objective(const Image& x, const Mat& k) {
    auto out=conv(x,k); double loss=0;
    for(const auto& row:out) for(double v:row) loss+=v*v/8;
    return loss;
}
int main() {
    Image image{{{{1,2,0}},{{0,1,3}},{{2,1,0}}}};
    Mat kernel{{{{1,0}},{{0,-1}}}};
    // STEP 2
    auto out=conv(image,kernel); Mat grad{};
    for(int a=0;a<2;++a) for(int b=0;b<2;++b)
        for(int i=0;i<2;++i) for(int j=0;j<2;++j)
            grad[a][b]+=out[i][j]*image[i+a][j+b]/4;
    // STEP 3
    Mat kp=kernel,km=kernel; double eps=1e-5;
    kp[0][0]+=eps; km[0][0]-=eps;
    double numeric=(objective(image,kp)-objective(image,km))/(2*eps);
    assert(std::abs(grad[0][0]-numeric)<1e-8);
    // STEP 4
    std::cout<<std::fixed<<std::setprecision(1)<<"output=";
    for(int i=0;i<2;++i) for(int j=0;j<2;++j)
        std::cout<<(i||j?" ":"")<<out[i][j];
    std::cout<<std::setprecision(6)<<"\nhalf_mse="<<objective(image,kernel)<<" gradient00="<<grad[0][0]<<'\n';
    std::cout<<"gradient_check=True\n";
    int conv_params=8*(1*3*3+1);
    std::cout<<"conv_params="<<conv_params<<" tiny_cnn_params="<<conv_params+512*10+10
             <<" mlp_params="<<64*32+32+32*10+10<<'\n';
}

逐步解释

按窗口做乘加

conv外层i、j枚举输出位置，内层a、b枚举核位置。Python生成嵌套列表，C++先把Mat置零再累加。核没有翻转，行为是互相关。

自查：不看输出手算右上位置为何等于−1。

共享核的反向路径

loss为平方和除8，grad为各位置输出乘输入再除4。上游梯度来自一半MSE，分母不能照抄损失的8。

自查：说明gradient00为−0.25中的四项各来自哪个窗口。

拷贝核并数值核对

Python逐行复制二维列表，C++复制array。仅扰动核左上项，重新执行同一objective。

自查：如果把Python的二维复制改为kernel.copy()，解释为什么可能破坏实验。

打印四个输出、损失、梯度和两种结构参数数。代码中的cnn_params包含分类头，不能只比较80个卷积参数。

自查：复算5210和2410，说明哪一层占大多数参数。

练习与参考答案

练习1

基础：把核改为全1，重新手算四个输出。

提示：

每个2×2窗口变成求和。

参考：

左上1+2+0+1=4，右上2+0+1+3=6，左下0+1+2+1=4，右下1+3+1+0=5；输出[4,6;4,5]。不要沿用原来的差值直觉。

练习2

实现：将核梯度核对扩展到4个元素，并增加偏置。

提示：

每个输出都加同一个b。

偏置对每个输出的局部导数为1。

参考：

核梯度逐元素中心差分；偏置梯度是四个输出的平均值，因为目标为0且损失是一半MSE。本例b=0时(0−1−1+1)/4=−0.25。更新时核与偏置梯度均须由旧参数计算。

练习3

迁移：增加一个2×2平均池化后再分类，重新算形状和参数量。

提示：

8×8变4×4，池化本身无可训练参数。

参考：

卷积仍80参数，池化后(8,4,4)共128值，分类头128×10+10=1290，总1370。它减少空间分辨率并改变表达能力，不能只报告更少参数；需在相同开发设置比较宏F1、logloss及误差样本。

开放讲解题

为什么共享参数的梯度要相加？

损失通过不同输出位置依赖同一参数。多变量链式法则把每条路径的贡献相加，随后按损失中的平均约定缩放。只取一个窗口会漏掉其余路径。

卷积让最终类别完全不受平移影响吗？

不能这样说。理想条件下卷积具有平移等变性，输入平移时特征也平移；最终分类是否不变还取决于池化、边界、步幅及分类头。必须用明确平移幅度和数据实验检验。
