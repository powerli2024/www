分布变化与遗忘：适配前先定义什么叫进步

01从一个能生成图像的模型，走到两个数据分布

预训练和微调首先描述训练的先后关系。项目B从随机权重学习原始图像域A，得到基础参数；再用域B更新其中全部或部分参数，称为适配。这里的基础模型只有小规模像素生成能力，不能因为使用了Transformer就把它当作已经拥有语言知识的大模型。开始本周前复制基础检查点到只读参考位置，记录来源训练配置、文件哈希和词表版本。

分布是样本出现的规律，而不只是文件夹名称。域A若偏好颜色0，域B把0与1交换，预测下一像素所需的条件概率就可能改变。但若一个变换恰好保持整体分布，B并不一定更难；因此先统计颜色频率并观察固定样本，不能仅凭“做了变换”宣称发生有意义的迁移。保持颜色ID集合大小不变，避免把未定义的编码错误误认为领域变化。

本周选择固定置换作为唯一变化：例如映射0→1、1→0，其他ID保持。置换要一对一，保证每种颜色有唯一逆映射；不要使用随机重抽颜色作为每次评估的目标，否则重复运行连问题都变了。对8×8替代数据，先去重完整图像，再按图像来源分组。对官方图像，同源增强版本也必须继承同一组ID。

操作顺序是原图分组、固定train/valid/test清单、分别在各集合内部变换。保存origin_id、split、domain、transform_version四列。训练可见A训练与B训练，配置选择只见开发集，A/B测试文件继续封存。颜色变换保留了图形来源，所以把A版放训练而B版放测试仍可能泄漏。

一起算一个例子

四张原图怎样分成两个域

  1. g0、g1只属于训练，g2只属于开发，g3只属于测试。

  2. g0的A版为[0,1,1,0]，B版为[1,0,0,1]；两个版本都归训练。

  3. g3也生成两版，但两版都归测试，不参与学习率选择。

A和B是域标签；train/valid/test是用途标签。二者形成交叉表，不互相替代。

02把新域学习与旧域遗忘分开计量

交叉熵衡量模型给真实下一个token分配了多少概率。固定样本、颜色词表、teacher forcing输入、计分位置和自然对数后，平均负对数概率越小越好。必须分别评估基础模型在A、B的损失，以及适配模型在A、B的损失，共四个数；只看适配后B损失无法判断旧能力是否保留。

新域收益定义为B上基础损失减去适配损失，所以正值代表新域改善。旧域遗忘定义为A上适配损失减去基础损失，所以正值代表旧域变差。两种差值的减法方向不同，因为它们分别希望表达“收益”和“退化”。遗忘为负意味着这个评价范围内A也改善；不要为了符合故事把它截断成零。

把每次适配画成一个点，横轴旧域遗忘，纵轴新域收益。左上方向同时更有利，但通常两个目标存在取舍。必须把不适配点(0,0)也画出来。可以预先规定“遗忘不超过0.2时最大化收益”，也可以只报告整张图；不能看到哪种方法占优后再改变选择规则。

本周程序中的概率是为了核对符号而手工给定的教学数据。运行它验证的是计分函数和划分检查，不是基础模型已经获得这些成绩。接入项目B时，把真实评估程序返回的四项损失替换进同样的差值函数，仍保留原始逐样本或逐批统计。

逐个认识符号

  • N：被计分token数，不是图像张数

  • p_i：模型给第i个真实token的概率；0<p_i≤1

  • log：自然对数

点击放大

收益与遗忘分别计算，符号不能混用。

逐个认识符号

  • G_B：新域收益

  • F_A：旧域遗忘

  • 上标0：基础模型，上标1：适配模型

  • 下标A、B：评估所在域

一起算一个例子

用四组概率算一遍

  1. 基础模型在A的真实token概率为0.8、0.7：损失=−log(0.56)/2≈0.289909。

  2. 基础在B为0.2、0.3：损失≈1.406705。适配在A为0.6、0.5：损失≈0.601986。

  3. 适配在B为0.7、0.8：损失≈0.289909。收益=1.406705−0.289909≈1.116796。

  4. 遗忘=0.601986−0.289909≈0.312077。

这组教学数据同时发生新域改善和旧域退化，不能压成一句“模型变好了”。

03把评价函数接到项目，而不是立刻扩大训练

先只做零更新检查：加载同一基础检查点两次，以eval模式评价同一开发集，四个损失中的对应两项应在预定数值容差内一致，差值应接近零。这一步能抓到随机采样、dropout、不同计分位置或数据顺序处理错误。生成图片可用固定种子展示，但交叉熵应直接由真实目标的log概率计算，不用采样出的token重新评分。

随后仅做50–200步资源试跑，在B训练集更新；步数与token数均记录。每一步究竟优化哪些参数、是否清梯度、何时停止，沿用第10周训练循环。保留训练损失、A开发损失、B开发损失，不把每次看到开发波动都当作必须改方案的理由。第19周才系统比较方法和学习率。

如果B损失没变，先检查实际加载的权重、梯度是否非零、优化器是否持有可训练参数，以及颜色变换是否真的被用于输入和目标。若A、B同时异常升高，排查学习率和编码；若训练好而开发差，排查过拟合与来源分组。每条解释都配一个能排除它的小检查，不用“数据太少”包办所有异常。

时间安排：2小时厘清域与分组，2小时手算和读程序，3小时接评价入口与资源试跑，2小时完成练习和口述，1–3小时记录问题。本周不要求得到显著迁移效果；要求把可比较的四个量测准。

一起算一个例子

零更新检查失败怎么办

  1. 同一模型第一次A损失0.42，第二次0.56，超出你预定的1e-6容差。

  2. 先在eval下固定同一小批输入与目标；若一致，再检查完整评价的数据清单和token计数。

  3. 不要直接报告遗忘0.14，因为两个结果尚未满足同一评价条件。

先修复可重复的测量，再讨论训练造成的改变。

Python

"""Teaching fixture: metrics and group splits, not trained model results."""
import math

# STEP 1
def cross_entropy(true_probabilities):
    assert true_probabilities
    assert all(0.0 < p <= 1.0 for p in true_probabilities)
    return -sum(math.log(p) for p in true_probabilities) / len(true_probabilities)

# STEP 2
groups = {"train": {"g0", "g1"}, "valid": {"g2"}, "test": {"g3"}}
assert not (groups["train"] & groups["valid"])
assert not (groups["train"] & groups["test"])
assert not (groups["valid"] & groups["test"])
image = [0, 1, 1, 0]
permutation = [1, 0]
transformed = [permutation[c] for c in image]
assert transformed == [1, 0, 0, 1]

# STEP 3
base_a = cross_entropy([0.8, 0.7])
base_b = cross_entropy([0.2, 0.3])
adapt_a = cross_entropy([0.6, 0.5])
adapt_b = cross_entropy([0.7, 0.8])
gain = base_b - adapt_b
forgetting = adapt_a - base_a
assert gain > 0 and forgetting > 0

# STEP 4
print("TEACHING FIXTURE; no model trained")
print("group_split=PASS permutation=PASS")
print(f"base_A={base_a:.6f} base_B={base_b:.6f}")
print(f"adapt_A={adapt_a:.6f} adapt_B={adapt_b:.6f}")
print(f"gain_B={gain:.6f} forgetting_A={forgetting:.6f}")

C++

// Teaching fixture: metrics and group splits, not trained model results.
#include <cassert>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <set>
#include <string>
#include <vector>

// STEP 1
double cross_entropy(const std::vector<double>& p) {
    assert(!p.empty());
    double total = 0.0;
    for (double value : p) { assert(value > 0.0 && value <= 1.0); total -= std::log(value); }
    return total / p.size();
}
bool disjoint(const std::set<std::string>& a, const std::set<std::string>& b) {
    for (const auto& id : a) if (b.count(id)) return false;
    return true;
}
int main() {
    // STEP 2
    const std::set<std::string> train{"g0", "g1"}, valid{"g2"}, test{"g3"};
    assert(disjoint(train, valid) && disjoint(train, test) && disjoint(valid, test));
    const std::vector<int> image{0,1,1,0}, permutation{1,0};
    std::vector<int> transformed;
    for (int c : image) transformed.push_back(permutation.at(c));
    assert((transformed == std::vector<int>{1,0,0,1}));

    // STEP 3
    const double base_a = cross_entropy({0.8,0.7}), base_b = cross_entropy({0.2,0.3});
    const double adapt_a = cross_entropy({0.6,0.5}), adapt_b = cross_entropy({0.7,0.8});
    const double gain = base_b - adapt_b, forgetting = adapt_a - base_a;
    assert(gain > 0 && forgetting > 0);

    // STEP 4
    std::cout << std::fixed << std::setprecision(6);
    std::cout << "TEACHING FIXTURE; no model trained\n";
    std::cout << "group_split=PASS permutation=PASS\n";
    std::cout << "base_A=" << base_a << " base_B=" << base_b << '\n';
    std::cout << "adapt_A=" << adapt_a << " adapt_B=" << adapt_b << '\n';
    std::cout << "gain_B=" << gain << " forgetting_A=" << forgetting << '\n';
}

逐步解释

概率到损失

Python的math.log与C++的std::log都用自然对数；函数先拒绝空输入和非法概率，再累加、除以token数。这里对已知概率求损失，真实模型应直接从稳定的log-softmax取数。

自查：把两个概率都改为1，损失应为0。

划分和颜色置换

Python集合&求交；C++的set.count查询是否存在。列表推导式与for循环逐颜色查置换表，C++的at还能检查越界。分组标识独立于图像像素。

自查：把g0放进test应触发断言。

保留四项损失

分别命名base_a、base_b、adapt_a、adapt_b，避免把域和时间搞混。两种语言使用相同输入和减法顺序，不把差值绝对值化。

自查：口算gain与forgetting的正负。

解释输出边界

固定六位小数只是显示精度，内部仍使用双精度。教学标记是输出的一部分；不能将这些人为概率抄进真实实验表。

自查：指出本程序没有优化器、训练循环或真实检查点。

练习1

基础：基础/适配在A为0.50/0.47，在B为1.20/0.90，计算收益和遗忘。

提示：

先写清减法方向。

参考：

G_B=1.20−0.90=0.30；F_A=0.47−0.50=−0.03。B改善0.30，A也改善0.03。只能描述这次设定，不能说适配永远不遗忘。

变化不再只涉及颜色。

检查类型比例与支持范围。

开放讲解题

不用公式讲清“学到更多”和“忘掉更多”。

在新域比较适配前后的预测损失，下降叫收益；在旧域做同样比较，上升叫遗忘。两个评价数据不同，所以一个变好不能代替另一个也好。

为什么固定颜色置换也不保证B更难？

难度取决于基础模型与变换后的实际分布。若分布对该置换对称，或者模型已学到相应关系，B可能不更难；必须用基础模型B损失和分布检查确认。

交付物

  • A/B来源与划分清单、固定置换表和基础检查点标识
  • 零更新四项损失检查，以及试跑记录或明确的阻塞原因
  • 收益/遗忘手算与3分钟解释

验收标准

  • 同源图像及所有变换版本没有跨用途集合
  • 能够独立算出G_B、F_A并解释负遗忘
  • 教学程序输出与真实模型结果分开保存；测试集未用于选择
